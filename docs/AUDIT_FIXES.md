## 已处理的刷新开销

- 属性侧栏在已有装等快照时复用目标统计；需要回退扫描时使用独立统计表，避免重复累加。
- 属性白名单、颜色、职业和专精映射移到文件级。
- 天赋系统查询缓存成功和未找到的结果，天赋配置、玩家天赋或玩家专精变化时失效。
- 宝石请求去重和重试截止时间仅在目标或装备变化时重置，同一装备重复刷新不会延长加载窗口。
- 侧栏 slotCache 条目复用；数字宽度按字体、字号、标志和缩放缓存。

## 不按缺陷直接改动的建议

- `windowEnd` 是过去两周采样的结束时间，不是推荐失效时间。把它当 expiresAt 会使刚生成的数据立即过期。现有显式 expiresAt 校验有效，本次补上其可见提示；没有擅自定义新的数据有效期。
- 已载入数据最多对应内置 40 个专精、两种模式，属于有限缓存。当前加载器执行后会释放专精载入闭包，直接按建议 wipe 数据会导致无法重新载入。压缩字段、共享附魔、LRU 等应作为数据格式改造另行测量和设计，报告中的 35%–50% 是估计，未作为实测结论。
- Sidebar 完整刷新仍需同步附魔、宝石和相关布局。只更新徽章可能遗留旧附魔状态；本次保留该行为。套装缓存、更多临时表池属于后续性能选项，不是已复现的崩溃。
- Options/ManagerBridge 元数据合并、旧客户端分支合并、未使用角色存档声明和纹理、只写变量及按需诊断命令，属于结构或包体整理；没有以修复错误为由删除兼容入口、存档声明或诊断功能。
- 没有删除报告列举的浏览器资料、采集输入、历史备份或发布 ZIP，也没有读取其中的隐私凭据。

## 验证与边界

执行 `tests/run_recommendation_tests.py --lazy-dir GearData --real-data --aggregate`：所有 Lua 文件通过 Lua 5.1 语法检查；11 种客户端语言、原生与 EllesmereUI 两种样式、80 份真实数据集均通过。新增测试覆盖旧数据提供者共存、空槽隔离、单槽 BIS、跨职业主属性、受限制值、异步任务、状态文字、评级刷新和缓存失效。

API 处理依据 Retail live 的 [SpecializationInfo 文档](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpecializationInfoDocumentation.lua) 与 [Unit 文档](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/UnitDocumentation.lua)。没有增加受保护界面操作。LibItemInfo 内部库修订号从 8 更新到 9，确保共享 LibStub 实例采用防护修复；该内部修订号与插件发布版本独立。

风险：中等，涉及观察统计和异步装等更新。自动测试使用模拟客户端 API，不能代替真实游戏中的受限制场景验证。建议 `/reload` 后检查：观察另一职业的空槽角色、已装备第二/第三名 BIS、换装后的个人属性、相同物品的多个按钮，以及缺失/不兼容数据库的状态提示。测试战斗和受限制单位时应保持无 Lua 错误。

仅将修改的运行 Lua 文件同步到已安装插件；测试、文档和采集器不复制。同步前在工作区 archive 创建原游戏文件备份，复制后逐文件核对 SHA256；回退时恢复该备份中的同名相对路径。
